# Terminal Notes

A blog built with [Astro](https://astro.build/) for things worth writing down
about tech, servers and coding. Every note carries a picture: a photograph
decoded onto a 132 × 37 character grid, generated by `tools/make-art.py` and
animated on a canvas by [ascii.rest](https://ascii.rest/) — the piece contract
and runtime by [@bas3line](https://github.com/bas3line) (MIT).

40 notes, 43 tags, 40 pictures. Static output: no server, no database, no
analytics, no third-party scripts except the ascii runtime and a 3 KB font
fallback that only browsers without block glyphs fetch.

## Run it

```bash
npm install
npm run dev        # http://localhost:4321
npm run build      # -> dist/
npm run preview    # serve dist/ on :4321
```

The art is generated, not hand-written, and the generated modules are
committed. To (re)build it — needs Python with Pillow and network access to
wallhaven:

```bash
python tools/make-art.py --all                    # one picture per note
python tools/make-art.py --only docker-has-two-stores
python tools/make-art.py --only <slug> --print     # print the ascii, write nothing
```

The queries live in `TOPICS` in that file; change a query and re-run for that
slug. Source photographs (and a JSON sidecar of ids and URLs) are cached in
`.art-src/`, which is git-ignored — only the generated modules in
`src/art/pieces/` are published.

## Deployment

Live at **<https://jbpixel52.github.io/terminal-notes/>** — GitHub Pages, built
by `.github/workflows/deploy.yml` on every push to `main`. The workflow installs
from the lockfile, runs the privacy gate, builds, runs the gate again over the
built output, and publishes `dist/` as the Pages artifact. The built output is
never committed: the pipeline is the only thing that writes what is served.

Two environment variables say where the site thinks it lives:

```bash
BASE_PATH='/terminal-notes' SITE_URL='https://jbpixel52.github.io'   # the defaults
BASE_PATH='' SITE_URL='https://notes.example.com'                    # a domain root
```

Every internal link goes through `url()` in `src/lib/url.ts`, which prefixes the
base, so the same commit deploys to a project path or to a domain root. The
thing to watch is the **navigation**: its hrefs come from `NAV` in
`src/consts.ts` rather than from a literal `href="/…"`, so a search-and-replace
over the templates will miss them. It did.

## Check it

```bash
npm run anon        # the privacy gate (see ANONYMIZATION.md)
npm run build
npm run verify      # every route in a real browser, screenshots to .verify/
npm run deployed    # the live site: sitemap, content, feed, robots
```

`verify` needs Playwright; it starts its own server, mounting `dist/` under
`--base-path` so the links resolve here as they do on the host. Use
`python scripts/verify_site.py --base-path ''` for a domain-root build.

```bash
# the interpreter that has Playwright, not necessarily the one called `python`
python3 -m playwright install chromium          # if the browser build is missing
export PLAYWRIGHT_BROWSERS_PATH=$HOME/.cache/ms-playwright
```

Playwright installs browsers to `$PLAYWRIGHT_BROWSERS_PATH` when that is set, and
the installed python package only accepts the exact chromium build it was
released with — so if the variable points somewhere unwritable the install fails
(or hangs) and every check reports a blank page.

On a machine running **npm 12 / Node 26**, `npm install` refuses this project's
git dependency (`ascii.rest`) and the mirror tarballs in its lockfile, and blocks
esbuild's postinstall, which breaks `astro build`:

```bash
# npm also resolves the git dependency over ssh; if this machine has no GitHub
# ssh key, rewrite that form to https for the run only
GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0='url.https://github.com/.insteadOf' \
GIT_CONFIG_VALUE_0='ssh://<user>@github.com/' \
  npm install --allow-git=all --allow-remote=all
npm install-scripts approve esbuild             # otherwise the build has no binary
```

CI installs fine on its own Node (22) for the same reason older npm never asked:
those refusals are newer defaults, not a broken lockfile.

`deployed` reads the live sitemap and requests every URL in it, then asserts
content rather than status: the home page's title and stylesheet, a note page's
no-JS picture and its source credit, the feed parsing with items whose links
carry the base, and robots.txt advertising the sitemap. A 200 is not a page.

## Writing a note

One Markdown file in `src/content/notes/`. The frontmatter is validated
against a schema, and the ascii piece name is checked against the library's
catalogue at build time, so a typo fails the build:

```yaml
---
title: "A short, specific title"
description: "One sentence that earns the click."
pubDate: 2026-10-05
tags: [docker, servers]
minutes: 7
ascii:
  piece: whale            # must exist in ascii.rest
  caption: "a caption for the frame"
---

## Section

Prose. Commands in fenced blocks. Errors quoted verbatim.
```

## Layout of the thing

```
src/
  content.config.ts        the note schema (title, date, tags, ascii, …)
  content/notes/           one file per note
  art/pieces/              generated pieces: one module per note's picture
  art/sources.js           where each photograph came from (generated)
  components/Art.astro     a generated picture: still + canvas + injector
  components/Ascii.astro   a catalogue piece from ascii.rest, validated by name
  layouts/                 BaseLayout (shell) + PostLayout (note + rail)
  pages/                   index, /notes, /notes/<slug>, /tags/<tag>, /art, …
  styles/global.css        the whole design system, ~720 lines
tools/
  make-art.py              wallhaven -> ascii piece modules (Pillow + urllib)
scripts/
  check-anonymized.mjs     privacy gate: shape checks + a git-ignored term list
  verify_site.py           browser harness: routes, headings, art, theme, screenshots
```

## Design notes

- Bold primary colours (red, yellow, blue, green) over a near-black ground, and
  a near-black and bone-white pair of grounds: the colour is spent on a gradient
  title, a header stripe, a rule under section headings, and rotating marks on
  tags and dates.
- The front page is a title, not a screenshot of a terminal: one big gradient
  wordmark that sweeps through the primaries, a blurred halo behind it, and a
  rule below. CSS only — three keyframes and a `@supports` guard for the clipped
  gradient — and it stops entirely under `prefers-reduced-motion`.
- Two faces: a bold display stack for headings and the wordmark, monospace for
  everything else, so the terminal voice survives the colour.
- Dark by default, with a light palette for readers whose system prefers it;
  the choice is stored and applied before first paint.
- Structure from hairline rules, with the primaries used as marks rather than as
  backgrounds.
- Motion respects `prefers-reduced-motion`: the ascii art holds its first
  frame, the CSS stops.
- The only client-side JavaScript is the theme toggle and the ascii runtime.
- Dates are formatted in UTC so two builds of the same commit agree.
